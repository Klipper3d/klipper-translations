# 多微控制器归位与探测

Klipper 支持一种机制，即使用连接到一个微控制器上的限位开关进行归位，而其步进电机则位于另一个不同的微控制器上。此功能被称为“多微控制器归位”（multi-mcu homing）。当 Z 探针位于与 Z 轴步进电机不同的微控制器上时，也会用到此功能。

该功能可用于简化接线，因为将限位开关或探针连接到更近的微控制器上可能更加方便。然而，使用此功能可能会导致在归位和探测操作期间步进电机出现“过冲”现象。

这种过冲是由于监控限位开关的微控制器与驱动步进电机的微控制器之间可能存在消息传输延迟所导致的。Klipper 代码的设计将这种延迟限制在 25 毫秒以内。（当启用多微控制器归位时，微控制器会周期性地发送状态消息，并确保在 25 毫秒内接收到对应的状态消息。）

因此，例如，如果以 10mm/s 的速度进行归位，则可能出现高达 0.250mm 的过冲（10mm/s * 0.025s == 0.250mm）。在配置多微控制器归位时，应充分考虑此类过冲情况。使用较慢的归位或探测速度可以减少过冲量。

步进电机的过冲不应影响归位和探测过程的精度。Klipper 代码会检测到过冲并在计算中予以补偿。然而，重要的是，硬件设计必须能够承受过冲而不对机器造成损坏。

要使用此“多微控制器归位”功能，硬件必须保证主机计算机与所有微控制器之间的延迟稳定且足够低。通常，往返时间必须持续低于 10ms。高延迟（即使只是短暂出现）都可能导致归位失败。

如果因高延迟导致失败（或检测到其他通信问题），Klipper 将报出“归位期间通信超时”错误。

请注意，对于具有多个步进电机的轴（例如 `stepper_z` 和 `stepper_z1`），要使用多微控制器归位功能，这些电机必须位于同一个微控制器上。例如，如果限位开关位于与 `stepper_z` 不同的微控制器上，则 `stepper_z1` 必须与 `stepper_z` 位于同一个微控制器上。
